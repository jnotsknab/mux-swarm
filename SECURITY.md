# Security Policy

This security policy applies to the mux-swarm project on GitHub - `github.com/jnotsknab/mux-swarm`.

## Priorities

Due to the rise of agentic AI and the ability of harnesses / tooling to fall into bad actors hands with virtually no regulation users and software are exposed to more cyber risks than ever before.

All mux-swarm maintainers and contributors must hold protecting data and mitigating attack surface paramount. Security vulnerabilities will always be treated with highest priority and will result in an on demand patch or minor version bump.

Additionally, one designated maintainer, currently `jnotsknab`, will run bi-weekly security scans on the repo and its dependencies to smoke out any future potential vulnerabilites / violations.

## Security/Bugfix Versions

Security and bug fixes are generally provided only for the last minor version.
Fixes are released either as part of the next minor version or as an on-demand patch version.

Security fixes are given priority and might be enough to cause a new version to be released.

## Reporting a Vulnerability

We encourage responsible disclosure of security vulnerabilities.
If you find something suspicious, we encourage and appreciate your report!

### Ways to report

In order for the vulnerability reports to reach maintainers as soon as possible, the preferred way is to use the "Report a vulnerability" button under the "Security" tab of the project.
This creates a private communication channel between the reporter and the maintainers.
